## 3. 履歴の書き換えとリポジトリの作り直し（記録）
- 理由: 33 件のコミットの作者に、大学のメールアドレスが入っていた。GitHub の PR の参照（`refs/pull/*`）は、強制 push では消せないため、**リポジトリを削除して作り直した**
- 方法: ローカルで `git filter-branch` により、作者情報を noreply アドレスに書き換え（コミット数は同じ・最新の内容は同一であることを検証）→ GitHub のリポジトリを削除 → 空のリポジトリを作成 → `main` だけを push
- 検証: 新しく clone して、履歴・メッセージ・ファイルのどこにも大学のメールがないことを確認
- 失ったもの: PR #1〜#8 と、Actions の実行履歴（記録は `workReport/` に残っている）
- バックアップ: `workingFolder\musicline-spotify-sync_backup_20261010.git`（古いメールを含むので、**公開しない**。不要になったら削除してよい）
- このリポジトリでは、ローカルのコミットの作者を noreply アドレスに設定済み（グローバル設定は未変更）

## 5. 注意点・今日の学び
- **GitHub のリポジトリを作るとき、README などを追加しない。公開範囲は Private のまま作る**（今回、空のリポジトリが Public で作られていた）
- 履歴のメールを消す場合は、強制 push だけでは足りない（PR の参照が残る）。リポジトリの作り直しが確実
- PowerShell 5.1 では `&&` が使えない。1 行ずつ実行する。`Get-Content | Set-Content` でファイルを書き換えない（日本語が壊れる）
- 実機で動かす場所は、メインのフォルダ。worktree には `data/` のコピーが必要になる
- 週に 1 回は `fetch` → `sync` を実行する。選曲が公開されるのは、2026-09-08 以降の回だけ
