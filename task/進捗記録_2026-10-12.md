## 4. 注意点・学び
- **マージの前後に、動作確認をしない**。PR のマージ前に実機で確認しても、古いコードの結果になる（5B で 1 回無駄になった）
- PowerShell 5.1: `&&` が使えない。`Get-Content | Set-Content` で日本語を書き換えない。ログを `type` で見るには、UTF-8 の BOM が必要
- 「時刻を逃した場合は起動後すぐに実行」（StartWhenAvailable）は、登録の直後にも、過去の取りこぼしに反応して実行される
- 無人で動く処理は、実機で一度、スケジューラ経由で通して確かめる
- GitHub のリポジトリは、**Private で作る**。メールの混入は、履歴の書き換えとリポジトリの作り直しでしか、確実には消せない
- Spotify の `refresh_token` は約 6 ヶ月で失効する（目安: 2027 年 4 月）

### 起きうる問題と対処
| 症状 | 対処 |
|---|---|
| 土曜に実行されなかった | PC が電源オフだった可能性。次に起動したときに自動で実行される。`Get-ScheduledTaskInfo -TaskName MusiclineSpotifySync` で、最終実行と結果を見る |
| 「追加予定が上限 50 曲を超えた」 | 長く実行していなかった可能性。`node src/index.js sync --dry-run` で内容を確認して、問題なければ `node src/index.js sync` を手動で実行する |
| NHK の API の形が変わった | `fetch` が失敗する。`logs` のログを見て、Claude Code に相談する（`src/nhk/client.js` を直す） |
| Spotify の仕様が変わった | `sync` が失敗する。同様にログを見て相談する（`src/spotify/**`） |
